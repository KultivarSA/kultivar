# `/docs` — Kultivar legal pages (GitHub Pages)

This folder is published by **GitHub Pages** at the URL you give the
App Store and Google Play during submission. Apple §1.5 and Play's
Data Safety policy both require a publicly-accessible privacy policy
URL — the in-app version (Settings → Legal) satisfies the *in-app*
requirement but **not** the store-listing URL.

## What's in here

| File | What it is |
|---|---|
| `index.html` | Landing page linking to Privacy + ToS |
| `privacy.html` | Static render of the in-app Privacy Policy |
| `terms.html` | Static render of the in-app Terms of Service |

All three are generated by `tools/generate_legal_html.py` from the
in-app markdown constants in `lib/legal/*.dart`. **Do not hand-edit**
— rerun the generator instead so the in-app + hosted versions stay
identical:

```sh
python tools/generate_legal_html.py
```

## Enabling GitHub Pages

One-time setup in the repository settings:

1. **Settings → Pages**
2. **Source:** Deploy from a branch
3. **Branch:** `main` · **Folder:** `/docs`
4. Save. GitHub builds the site automatically; URL appears within ~30 s.

Once enabled the URLs are:

- `https://<owner>.github.io/<repo>/` → index
- `https://<owner>.github.io/<repo>/privacy.html` → Privacy Policy
- `https://<owner>.github.io/<repo>/terms.html` → Terms of Service

Use these URLs in:

- **App Store Connect** → App Privacy → Privacy Policy URL
- **Google Play Console** → Store presence → Main store listing → Privacy Policy
- **`store_metadata/`** marketing copy where the policy URL is referenced

If you have a custom domain (`kultivar.app`, etc.), drop a
`CNAME` file in `/docs` with the bare domain and configure DNS as
GitHub Pages instructs — both files in this folder become accessible
under the custom domain immediately.

## Theming

The pages render with Kultivar's dark colour tokens
(`#0A0A0F` background, `#00C896` primary, `#F0F0FF` text). The CSS is
in-lined per page so there's no asset request beyond the HTML itself —
keeps load time fast and avoids cache-busting headaches.

The pages are intentionally minimal: no fonts loaded from CDNs (system
fonts only — better privacy for visitors and faster load), no
JavaScript, no analytics. That's the **right** posture for a privacy
policy page.

## Regeneration cadence

Re-run the generator whenever:

- `lib/legal/privacy_policy.dart` or `lib/legal/terms_of_service.dart`
  changes (typo, policy update, new section)
- The brand colours in the in-line CSS need to shift
- You add a new page to the legal flow (e.g. cookie policy)

Generated HTML is committed to git on purpose: CI doesn't run the
generator, and serving the pages should never depend on a build step
that might fail mid-pipeline.
